# Reality v3: Physical-AI integration layer

Reality v3 is the integration layer above the existing deterministic geometry,
branching, graph, navigation, articulation, and optional MuJoCo capabilities.
It does not make an LLM a geometry authority. A model may propose an action;
Reality must measure, validate, preview, and record the result.

## Product contract

Every v3 integration must provide a truthful capability descriptor. An adapter
cannot claim Blender, Unity, Unreal, ROS, Isaac, or robot-control support merely
because it can export JSON. Unsupported operations raise a typed error. Imported
geometry stays represented by Reality's existing objects and backends; adapters
must not implement a competing geometry engine.

The first implemented v3 component is `reality.integrations`:

- `IntegrationDescriptor` identifies an adapter and its exact capabilities.
- `IntegrationStatus` probes whether an adapter's native runtime is actually
  usable and reports its runtime version where available.
- `IntegrationRegistry` is explicit and process-local; it does not execute
  arbitrary uploaded scripts or auto-discover untrusted plug-ins.
- `SceneManifestIntegration` is a real, strict `reality-scene/v1` JSON
  interchange adapter for object AABBs, transforms, units, and explicit rigid
  body properties. It intentionally does not claim mesh, CAD, material,
  animation, or physics fidelity.
- `MuJoCoSceneIntegration` compiles actual MJCF with the optional MuJoCo
  runtime and imports supported primitive geom bounds or exports one oriented
  bounding box per Reality object. `inspect_scene()` additionally reports real
  compiled joint, actuator, and sensor declarations without pretending they
  are all representable by a `World`. It reports all lost mesh/CAD, material,
  contact, and dynamic-state semantics. `rollout()` runs a bounded local
  simulation only after validating named controls against the source model's
  declared actuator ranges; it cannot issue a hardware command.

## Milestones and release gates

| Milestone | Deliverable | Acceptance gate |
| --- | --- | --- |
| V3.1 | Integration contract and secure interchange | Round-trip tests preserve IDs, bounds, transforms, units, and explicit physics inputs; malformed input is rejected. |
| V3.2 | Blender add-on | Tested inside a specified Blender release; imports named mesh objects and transforms; destructive writes require a preview and user confirmation. |
| V3.3 | Physical-AI simulator adapter | **Started:** MuJoCo 3.14 MJCF primitive-geometry interchange and real joint/actuator/sensor inspection compile real scenes in tests. Full kinematic-tree, mesh, dynamic-state, and command mapping remains incomplete. |
| V3.4 | Game-engine bridge | Tested in the engine's supported version with coordinate/unit mapping, hierarchy, collision-layer mapping, and a live-sync conflict policy. |
| V3.5 | MCP/agent production boundary | Tool schemas expose inspect/measure/plan/preview/apply; edit tools require confirmation; the server delegates geometry to Reality. |

No milestone is complete because a mock responds successfully. Each needs a
repeatable integration test running the real host runtime in CI or a documented
manual validation record when that host cannot run on CI.

## Physical-AI safety rules

1. AI text is intent, never a numerical fact or collision verdict.
2. A coordinate frame and units are required before spatial data is combined.
3. A plan is validated in a branch before it can alter the source world.
4. Any adapter write must report changed IDs and preserve an audit record.
5. Robot commands remain disabled by default and require an explicit deployment
   policy, confirmation, and a separate safety controller. Reality alone is not
   a robot safety certification.

## First v3 API

```python
from pathlib import Path

import reality

registry = reality.IntegrationRegistry([reality.SceneManifestIntegration()])
adapter = registry.get("reality-scene")
assert registry.statuses()[0].available

adapter.export_world(world, Path("cell.reality.json"))
restored, evidence = adapter.import_world(Path("cell.reality.json"))
print(evidence.changed_object_ids)
```

The manifest is an interoperability baseline, not a substitute for `.blend`,
USD, STEP, a game project, or a simulator scene.

## Physical-AI simulator example

Run `python examples/mujoco_rollout.py` after installing `reality[physics]`.
The example compiles MJCF, inspects one joint/actuator/sensor, simulates a
validated actuator control, and prints machine-readable results. It does not
connect to or control a physical robot.

The current verified status and deliberate limitations are in
[V3_AUDIT.md](V3_AUDIT.md).
