# Reality v4: Shared physical-world platform

V4 is in foundation phase, not an implemented release. It starts only after
the v3 integrations have real-host validation. Its goal is a secure shared
world ledger: teams, applications, simulators, and approved agents can refer to
the same versioned physical-world state and reproduce a result.

## Implemented local foundation

`WorldLedger.capture(world)` now creates an immutable local provenance record
from a `WorldSnapshot`. It fingerprints backend-neutral authored state,
including objects, transforms, explicit physical properties, agents,
articulations, units, and navigation configuration. `append_snapshot()` creates
a new ledger with a source/target digest transition and cannot mutate the
previous ledger, snapshot, or world.

Opaque mesh and CAD references are deliberately excluded from the state digest.
Applications can supply a separately computed `source_digest` for source-asset
integrity. A coordinate frame is recorded only when a caller explicitly supplies
one; Reality does not infer it.

Run `python examples/world_ledger.py` for a machine-readable branch ledger.
The exact verified scope and exclusions are in [V4_AUDIT.md](V4_AUDIT.md).

## V4 platform primitives

1. **World identity and provenance** — immutable world/version IDs, source
   format, source hash, unit/frame declaration, importer version, and evidence
   for every derived result.
2. **Collaborative change ledger** — append-only changes, reviews, merge rules,
   conflict detection, and branch comparison for physical scenes.
3. **Live digital-twin adapters** — bounded, authenticated updates from sensors
   and simulators with timestamps, coordinate-frame transforms, and stale-data
   detection.
4. **Verified planning** — agents create candidate plans; Reality validates
   geometry and constraints; a simulator or safety system separately validates
   dynamics and execution policy.
5. **Federated deployment** — local, cloud, and edge workers with tenant
   isolation, object storage, audit logs, rate limits, reproducible job inputs,
   and no implicit training on customer data.

## Non-negotiable constraints

- No LLM may overwrite source geometry or assert physical facts without a
  deterministic Reality result attached as evidence.
- AABB results remain labelled approximate when exact mesh/CAD analysis is not
  used.
- Live data never silently replaces an authored scene; it forms a timestamped
  observation or an explicit approved change.
- Hardware actuation requires a deployment-specific safety review and is never
  enabled by package installation.

## Entry criteria for implementation

V4 coding begins only when v3 has at least one real DCC/engine adapter and one
real physical-AI/simulator adapter validated in their native hosts, with
documented versions and repeatable tests. Until then this document is the
platform contract, not a release claim.
