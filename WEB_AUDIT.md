# Reality developer website audit

`REALITY_WEB_STATUS=PARTIAL`

The website and API run locally against the real Reality package. They are not
publicly deployed, and live SMS has not been exercised because no Twilio Verify
credentials were configured on the development machine.

## Verified on 2026-10-02

- Chromium 145.0.7632.6 completed the website flow: email account creation,
  API-key creation and one-time reveal, real OBJ upload/analysis, structured
  summary, GLB preview fetch, part listing, and a real Reality measurement.
- The model-viewer WebGL component loaded and rendered the cube. A 390-pixel
  mobile viewport had no horizontal overflow. Screenshots are generated by
  `python tools/browser_smoke.py` under `output/playwright/`.
- The FastAPI suite verified two-account file-list isolation, phone-auth
  validation and fail-closed behavior without SMS configuration, a provider
  approval-to-session flow, and rejection of foreign-origin cookie mutations.
  Its provider approval fixture does **not** prove live SMS delivery.
- The full repository suite: 131 passed, 5 skipped (CUDA driver unavailable),
  1 Starlette deprecation warning. Ruff formatting/lint and strict mypy for
  `src/reality` passed.
- The current `0.2.1` source built into a new wheel and sdist using locally
  installed Hatchling; Twine checks passed. A fresh Python 3.11 environment
  installed the wheel with dependencies and imported `reality` from its
  `site-packages`. Generated OBJ inspection and measurement passed. This is a
  local development build, not a new PyPI release.
- PostgreSQL 16 in a disposable local container accepted migrations 001, 002,
  and 003. A FastAPI client then created an account and API key, uploaded a
  generated OBJ, and received a real Reality model summary from that database.
  The disposable container was stopped and removed afterward.

## External checks still required

- Configure a real Twilio Verify account/service and test sending and checking
  an SMS to a consenting phone number. The API contains no fixed-code bypass.
- Apply `003_phone_auth.sql` to a real PostgreSQL deployment and test API
  replicas, the worker, production object storage, and TLS. The local
  PostgreSQL smoke test does not validate the full Compose stack or deployment.
- Publish the website/API to a real domain, configure CORS and HTTPS cookies,
  then repeat the browser flow against that deployment.
- Pin and self-host the WebGL viewer dependency before production, and include
  the browser smoke test in CI. The current viewer loader uses an unpinned CDN
  URL, so local rendering success is not a supply-chain or availability proof.

## Reproduce local checks

```powershell
$env:PYTHONPATH = "$PWD\apps\api;$PWD\apps\mcp"
python -m pytest tests apps/api/tests apps/mcp/tests -q
ruff format --check .
ruff check .
mypy src/reality
node --check apps/web/app.js
$realityBuild = Join-Path $env:TEMP ('reality-build-' + [guid]::NewGuid().ToString('N'))
python -m build --no-isolation --outdir $realityBuild
python -m twine check "$realityBuild\*"
```

Start the API with a new SQLite development database and
`REALITY_CORS_ORIGINS=http://127.0.0.1:3000`, then run `python tools/dev_web.py`
and `python tools/browser_smoke.py`. The browser script requires Playwright and
Chromium in the development environment.
